# Tracker_Marketing «Контур» — трекер контента (MVP)

Трекер контента для продакшн-студии: весь путь материала от идеи до публикации — на одной канбан-доске.

## Запуск

- **Просто откройте файл `index.html` двойным кликом** в браузере (Chrome / Edge / Firefox).
  Ничего устанавливать не нужно — всё работает офлайн, данные хранятся в localStorage браузера.
- Демо-данные (5 клиентов, команда, 9 задач) загружаются автоматически при первом запуске.
  Сбросить их можно ссылкой «обновить демо-данные» справа над доской.

## Как переключать роли (демо-режим)

В правом верхнем углу есть селектор «Вы вошли как» — переключитесь между ролями,
чтобы увидеть доску глазами каждого участника:

| Роль | Что видит | Что может |
|---|---|---|
| Арт-директор (Ирина) | все задачи и колонки, фильтры, сводка | создаёт задачи, назначает исполнителей, двигает карточки, фильтрует |
| Копирайтер (Анна, Марк) | свои задачи + колонку «Идея» | двигает свои задачи «Пишется» → «Текст готов», добавляет текст/ссылки |
| Дизайнер (Олег, Лена) | колонки «На дизайне» и далее | двигает свои задачи «На дизайне» → «На согласовании», прикрепляет макеты |
| Клиент (Клиенты 1–5) | только «На согласовании» по своим проектам | комментарии «Принято» / «Правки», публикация |

## Правила переходов (по ТЗ)

1. «Идея» → «Пишется» — только арт-директор (с назначением копирайтера).
2. «Пишется» → «Текст готов» — копирайтер-исполнитель.
3. «Текст готов» → «На дизайне» — арт-директор (с назначением дизайнера).
4. «На дизайне» → «На согласовании» — дизайнер-исполнитель.
5. «На согласовании» → «Опубликовано» — клиент; возврат с правками автоматически
   создаёт комментарий с текстом клиента и возвращает задачу дизайнеру.

Карточки можно перетаскивать мышью — при нарушении правила перехода появится подсказка.
Тот же переход доступен кнопками в карточке и в окне задачи (работает и на сенсорных экранах).

## Публикация на GitHub

Приложение полностью статическое — сервер и сборка не нужны, идеально подходит GitHub Pages.

### Способ 1. Через браузер (без установки программ)

1. Создайте репозиторий: [github.com/new](https://github.com/new) — имя, например `kontur-tracker`, visibility **Public**.
2. На странице репозитория: **Add file → Upload files** → перетащите все файлы проекта (включая `.gitignore`) → **Commit changes**.
3. Включите публикацию сайта: **Settings → Pages → Build and deployment** → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
4. Через 1–2 минуты сайт появится по адресу `https://<ваш-логин>.github.io/kontur-tracker/`.

### Способ 2. Через Git (если установлен)

```bash
git init
git add .
git commit -m "Контур — трекер контента (MVP)"
git branch -M main
git remote add origin https://github.com/<логин>/kontur-tracker.git
git push -u origin main
```

Затем включите Pages так же, как в шаге 3 способа 1.

> **Про данные:** трекер хранит задачи в localStorage браузера. На опубликованном сайте
> каждый посетитель видит демо-данные и сохраняет свои правки локально — общей базы
> у статической версии нет. Для командной работы с общими данными нужен сервер
> (см. вариант Flask/Node из обсуждения).
